# ***Honeypot-системы***

***Honeypot-системы (или узлы-приманки)*** - вычислительные системы, которые разворачиваются в сети. Приманки, как следует из названия, предназначены для того, чтобы привлечь внимание злоумышленников, чтобы атака была направлена на поддельную систему, а не на оригинальную, где они смогут нанести серьезный ущерб компании 

***Honeypot-системы решают следующие задачи:*** 
- Сбор информации о злоумышленнике 
- Отвлечение атакующего от ценных ресурсов системы 
- Оценка эффективности применения других средств защиты 
# ***Классификация Honeypot-систем***

- **Honeypot-системы** - можно классифицировать по назначению (исследовательские и производственные) и уровню взаимодействия (низкий, средний и высокий)
- **Исследовательские** - приманки предназначены для сбора информации о кибератаках
- **Производственная** - honeypot-система используется в среде организации для ее защиты и снижения рисков
- **Honeypot-системы с низким уровнем взаимодействия** - это, прежде всего, производственные приманки, которые используются для имитации тех сервисов, которые нельзя использовать для получения полного доступа к узлу 
- **Honeypot-системы со средним уровнем взаимодействия** - более сложные, чем приманки с низким уровнем взаимодействия, они предоставляют больше векторов атаки для злоумышленников 
- **Honeypot-системы с высоким уровнем взаимодействия** - это узлы с полнофункциональными системами и приложениями. После проникновения злоумышленника внутрь такой приманки производится анализ его активности в системе

# ***Обнаружение разведки Active Directory при помощи Honeytoken***

Для обнаружения сканирования Active Directory возможно создание поддельной учетной записи домена. При попытке логина с использованием данных поддельной учетной записи в журнале событий (eventvwr. msc) появится соответствующая запись. Данная запись будет содержать идентификатор события 4625 и имя созданной поддельной учетной записи

Помимо данного события на контроллере домена может быть зарегистрированы события с идентификатором 4771. Когда пользователь вводит данные учетной записи домена, рабочая станция связывается с локальным контроллером домена и запрашивает TGT. Если имя пользователя и пароль верны и учетная запись пользователя проходит проверки состояния и ограничений, контроллер домена предоставляет TGT и регистрирует событие с идентификатором 4768 (билет аутентификации предоставлен). Если запрос билета завершается неудачей, Windows регистрирует это событие с идентификатором 4771

Для обнаружения атаки Pass-the-Hash может быть использована техника **HoneyHash**. Она включает в себя размещение учетных данных для поддельной учетной записи в памяти LSASS на целевой системе. Если злоумышленник попытается воспользоваться учетными данными для атаки PtH, событие будет зарегистрировано для дальнейшего анализа. Такие события могут быть зарегистрированы при помощи Sysmon. При попытке проведения атаки PtH журнал событий будет содержать события с идентификаторами 4625 (неудачная попытка входа) и 10 (попытка доступа к процессу lsass.exe процессом mimikatz.exe)

***Для того, чтобы сделать поддельную учетную запись привлекательнее для злоумышленника, возможно выполнение следующих действий:***
- Перепрофилировать старую учетную запись, которая была неактивна. Это «старит» аккаунт и обеспечивает некоторый уровень легитимности
- Выполнить вход в систему хотя бы один раз (желательно больше)
- Совершить хотя бы одну попытку ввода неверного пароля
- Добавить учетную запись в привилегированную группу AD, установив при этом автоматически сгенерированный пароль
# ***Примеры Honeypot-систем с низким уровнем взаимодействия***

### **Honeypot-системы для баз данных**

- **[Delilah](https://github.com/SecurityTW/delilah)** — действует как уязвимый экземпляр Elasticsearch, который обнаруживает и идентифицирует паттерны атак, попытки сканирования и команды загрузки (в частности, «wget» и «curl»).
- **[Nosqlpot](https://github.com/torque59/nosqlpot)** — приманка с открытым исходным кодом для баз данных nosql, которая автоматизирует процесс обнаружения злоумышленников и регистрации инцидентов атак. Механизмы моделирования развертываются с использованием фреймворка Twisted.
- [**mysql-honeypotd**](https://github.com/sjinks/mysql-honeypotd) — honeypot с низким уровнем взаимодействия, имитирующий работу БД MySQL.
### **Honeypot-системы для** **веб-приложений:**

- **[Glastoph](https://github.com/mushorg/glastopf)** — Реализован на языке Python версии 2.7, имеет ряд шаблонов html-страниц. Приложение, которое имитирует данная ловушка, может быть дописано или вовсе переделано в зависимости от нужд пользователей. В данном honeypot присутствует эмуляция популярных типов атак: удаленное включение файлов (RFI) через встроенную песочницу PHP, включение локальных файлов (LFI) из виртуальной файловой системы и внедрение HTML через запросы POST.
- **[DShield](https://github.com/DShield-ISC/dshield)** — Web Honeypot состоит из 3 элементов: клиент, набор шаблонов и система логирования событий. Все веб-запросы, поступающие на приманку, передаются модулю-клиенту. Клиент пытается сопоставить запрос к веб-приложению с одним из шаблонов, установленных в приманке. Если подходящий шаблон найден, он отправляется пользователю, который произвел запрос. Если шаблон недоступен, возвращается веб-страница по умолчанию. В обоих случаях конкретный запрос веб-приложения регистрируется и отправляется в центральную базу данных DShield.
- **[Honeyhttpd](https://github.com/bocajspear1/honeyhttpd)** — это honeypot-платформа веб-сервера на основе Python. HoneyHTTPD позволяет создавать свои ответы с помощью Python на уровне протокола HTTP, чтобы имитировать ответы серверов Apache/Tomcat. Для более гибкой настройки требуется изменение исходного кода обработчиков запросов.
### **Honeypot-системы для сетевых** **протоколов:**

- **[DDoSPot](https://github.com/aelth/ddospot)** — honeypot для отслеживания и мониторинга атак распределенного отказа в обслуживании (DDoS) на основе UDP. В настоящее время платформа поддерживает следующие службы/серверы-приманки: NTP-сервер, SSDP-сервер, CHARGEN-сервер, Mock-UDP-сервер.
- **[HoneySMB](https://github.com/rosehgal/HoneySMB)** — honeypot с высоким уровнем взаимодействия для эмуляции работы SMB-сервера.
- **[Conpot](https://github.com/mushorg/conpot)** — это приманка для АСУ ТП, целью которой является сбор информации о мотивах и методах злоумышленников, нацеленных на системы промышленного управления. Поддерживает распространенные протоколы, используемые на устройствах АСУ ТП: IEC104, http, ftp, tftp, modbus, snmp.
- [**CiscoASA Honeypot**](https://github.com/cymmetria/ciscoasa_honeypot) — honeypot с низким уровнем взаимодействия для компонента Cisco ASA, способен обнаруживать попытки эксплуатации CVE-2018-0101, уязвимости DoS и удаленного выполнения кода.
- **[Kippo](https://github.com/desaster/kippo)** — SSH-honeypot среднего взаимодействия, предназначен для регистрации bruteforce атак и, что наиболее важно, всего взаимодействия с SSH-оболочкой, выполняемого злоумышленником.
- **[Cowrie](https://github.com/cowrie/cowrie)** — honeypot для SSH и Telnet со средней и высокой степенью взаимодействия, предназначенная для регистрации bruteforce атак и взаимодействия с SSH-оболочкой, выполняемого злоумышленником. В режиме среднего взаимодействия (SSH-оболочка) он эмулирует систему UNIX на Python, в режиме высокого взаимодействия (прокси) он функционирует как прокси-сервер SSH и telnet для наблюдения за поведением злоумышленника в системе.

# ***Установка и настройка Honeypot-системы T-Pot***

1. Установить ОС Debian 11.
2. В установленной ОС открыть терминал, заменить пользователя оболочки на root: `su`.
3. В установленной ОС установить git: `apt-get install -y git`.
4. Склонировать репозиторий проекта T-Pot: `git clone [https://github.com/telekom-security/tpotce](https://github.com/telekom-security/tpotce)`.
5. Перейти в директорию с shell-скриптом для установки необходимых модулей: `cd tpotce/iso/installer/`.
6. Выполнить команду для установки необходимых модулей: `./install.sh --type=user`.
7. В процессе установки выбрать конфигурацию T-Pot: Standard, установить имя пользователя и пароль для веб-интерфейса



# ***Примеры продуктов класса Distributed Deception Platforms***

***Deception-технология*** - представляет собой использование методов активных методов обмана злоумышленников с применением специальных ловушек, приманок и других приемов дезинформации

***Deception-платформы*** представляют собой централизованные системы управления, которые создают, распространяют и управляют всей эмулируемой средой и связанными с ней компонентами архитектуры
