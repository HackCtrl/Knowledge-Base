# ***Постановка задачи***

***Разведка*** - первоначальный этап атаки на сетевую инфраструктуру. Техники защиты направлены на минирализацию получения информации при использовании метологий OSINT на первых порах, что позволяет предотвратить дальнейшую атаку на сеть 
## ***Основные понятия***

***OSINT (Open Source Intelligence)*** - это процесс сбора, анализа и использование открытых источников информации для получения полезных данных. К открытым источникам относятся все ресурсы, к которым не требуется специального доступа: социальные сети, блоги, форумы, публичные базы данных и другие 

***Цель злоумышленника*** - найти как можно больше информации о целевой организации: доступные публичные сервисы, критичные ресурсы компании, используемые технологии 
## ***Honeytoken***

***Honeytoken*** - это ложная информация, которая размещается в системе или на сайте компании, чтобы привлечь внимание злоумышленников и определить факт несанкционированного доступа к данным. Honeytoken может быть представлен в виде фиктивных учетных записей, файлов или документов, которые содержат ложную информацию 

***Размещение Honeytoken'ов в организации, как правило, включает в себя несколько шагов:***

1. Создание Honeytoken в зависимости от эмулируемых данных (например, поддомен организации).
2. Honeytoken размещается на ресурсе внешнего периметра организации (в случае с OSINT), например, поддельные учетные данные, используемые для удаленного доступа к высокочувствительным ресурсам, намеренно размещаются в обсуждении на форуме.
3. Систему управления Honeytoken связывают с системой обнаружения вторжений (IDS) или платформой управления информационной безопасностью и событиями безопасности (SIEM).
4. После срабатывания оповещения вступает в силу план реагирования на инциденты организации.
5. Данные, собранные в результате анализа события срабатывания обнаружения, затем могут быть использованы для принятия мер безопасности. Информация, полученная в результате использования Honeytoken, дает представление о частях сети, подвергающихся наибольшему риску, а также о типах инструментов, необходимых для защиты этих областей.
## ***Настройка получения уведомлений о проведении OSINT***

***При проведении OSINT злоумышленник нацелен на следующие файлы:*** 
- Доменные имена, которые принадлежат организации 
- Почтовые адреса сотрудников 
- Социальные сети организации и ее сотрудников 
- Исходный код из репозиториев в системах контроля версий 
## ***DNS Canarytoken***

***DNS canarytoken*** - это механизм обнаружения несанкционированного доступа к DNS-серверам. Он предоставляет собой уникальный DNS-запрос, который не должен быть использован нормальными пользователями или приложениями. Если кто-то попытается использовать этот запрос, это будет сигналом о возможной атаке. DNS canarytoken может быть размещен на DNS-сервере или в зоне DNS-имен и может быть настроен для определенных типов DNS-запросов или все всех запросов 

***Canarytokens*** - уведомления об обращении к поддельному домену присылаются на почтовый адрес 

В данной утилите используется система оповещения через почтовый адрес, настройка средства осуществляется при помощи файла окружения. Рассылка уведомлений может осуществляться как при помощи внутреннего SMTP-сервера, так и при помощи сторонних служб для рассылки писем. Для настройки уведомлений с использованием внутреннего SMTP-сервера необходимо указать следующие данные:

- Адрес SMTP-сервера, с помощью которого будет осуществляться отправка уведомлений;
- SMTP-порт;
- Учетные данные для SMTP-сервера;
- Почтовый адрес, с которого будет производиться отправка уведомлений;
- Тема письма с уведомлением.

***Пример настройки уведомлений об использовании токена в Telegram:***

1. Создать Telegram-бота, получить access-token бота, с помощью которого будет осуществляться рассылка.
2. Создать сервер для размещения кода бота: настроить собственный сервер с внешним IP-адресом либо воспользоваться сервисами по аренде виртуального выделенного сервера (VDS).
3. Зарегистрировать адрес сервера в Telegram в качестве endpoint'a для обмена сообщениями.
4. Указать в утилите API-ключ для доступа к telegram-боту, а также ссылку на полученный webhook.

***В общем виде алгоритм размещения и внедрения поддельных данных может быть представлен следующими шагами:***

1. Определение типа эмулируемых данных (DNS, email, API-ключ и т.п.).
2. Создание и размещение данных на внешних сервисах.
3. Настройка системы уведомлений об использовании поддельных данных (SMTP, Telegram, SIEM).
## ***Другие данные, интересные для злоумышленника***

## ***E-mail адреса***

Обычно почтовые адреса расположены в том же домене, что и остальные информационные ресурсы организации. Злоумышленники пользуются этим фактом и используют средства автоматизации поиска. Для обнаружения факта компрометации внутреннего почтового адреса возможно зарегистрировать поддельный e-mail, который будет выступать в качестве honeytoken’а. При выявлении аномальной деятельности (спам-рассылка, множественные попытки входа, использование почтового адреса в качестве логина при аутентификации, запросы к БД, содержащие сгенерированный e-mail) система обнаружения должна генерировать уведомление.
## ***Репозитории Git***

Очень часто в оставленных в публичном доступе репозиториях присутствуют API-токены доступа ко внутренним сервисам организации. Злоумышленники могут пользоваться этим при проведении разведки. Эмуляция и отслеживание аномальной активности, связанной с поддельным токеном (или даже целым endpoint’ом) позволит выявить факт компрометации исходного кода.

Для автоматизации и эффективного отслеживания деятельности злоумышленника на внешнем периметре компании можно использовать средство «Manuka», которое представляет собой агрегатор указанных выше методик по созданию honeytoken’ов.
