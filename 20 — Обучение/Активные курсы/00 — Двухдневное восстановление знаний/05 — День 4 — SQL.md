## Подготовка: подключение и учебные данные

### Что вспомнить о подключении

PostgreSQL — СУБД, а SQL-клиент — программа, через которую отправляются запросы. Для подключения нужны тип СУБД, хост, порт, имя базы, пользователь и пароль. Успешное соединение ещё не гарантирует наличие нужных таблиц и прав. Проверь выбранную базу и схему до запуска запроса.

В [[2. Подключение к БД]] есть реквизиты учебного сервера. Здесь они не повторяются. Для этого тренажёра используй собственную изолированную учебную базу, не рабочую систему.

## Блок 1. База запроса: SELECT, сортировка и условия

### 1. SELECT, FROM и алиасы

`SELECT` отвечает «что показать», `FROM` — «откуда взять». Порядок выражений в SELECT задаёт порядок столбцов. Алиас столбца меняет подпись результата, а не структуру исходной таблицы. Алиас таблицы сокращает обращение к её полям.

```sql
SELECT u.id, u.username AS login, u.date_joined AS registered_at
FROM users AS u
ORDER BY u.date_joined DESC, u.id ASC;
```

Читай по строкам: из users под именем u берутся три столбца; два получают новые подписи; более поздняя регистрация идёт первой, а при одинаковом времени меньший id — раньше. `AS` допустимо опускать, но в повторении оставляем его для ясности.

`*` выбирает все столбцы; `u.*` — все столбцы конкретного источника. Это удобно при исследовании, но в задаче с точным списком колонок перечисляй их явно.

**Вспомни:** чем порядок столбцов отличается от порядка строк? Что изменится при перестановке двух полей в ORDER BY?

**Старая задача:** [[Практика 1. Задача 1]] — id, username, email, date_joined; дата по убыванию, id по возрастанию.

**Новая S1:** вывести id, username под именем login и score только активных пользователей; score по убыванию, id по возрастанию. Сначала предскажи id результата.

> [!success]- Проверка S1
> ```sql
> SELECT id, username AS login, score
> FROM users
> WHERE is_active = 1
> ORDER BY score DESC, id ASC;
> ```
> Последовательность id: **4, 2, 5, 1**.

### 2. Сравнения, AND, OR, NOT и NULL

Операторы: `=`, `<>` / `!=`, `>`, `<`, `>=`, `<=`. AND требует истинности обоих условий; OR — хотя бы одного. AND связывает сильнее OR, поэтому нужную группировку записывай скобками.

`NULL` означает неизвестное или отсутствующее значение. Это не число 0 и не пустая строка. `IS NULL` проверяет отсутствие, `IS NOT NULL` — наличие. Сравнение `company_id <> 7` не включает строки с NULL: результат сравнения неизвестен, а WHERE оставляет только истину.

```sql
SELECT id, username, company_id, score
FROM users
WHERE is_active = 1 AND (score > 500 OR company_id = 7)
ORDER BY id;
```

В стенде проходит только id=1. Если убрать скобки, неактивный id=3 тоже пройдёт через `company_id = 7`.

Порядок изученных частей: `FROM/JOIN → WHERE → SELECT → DISTINCT → ORDER BY`. Поэтому алиас из SELECT обычно нельзя использовать в WHERE того же уровня:

```sql
SELECT id, score + 1 AS next_score
FROM users
WHERE score + 1 > 300
ORDER BY next_score DESC, id;
```

**Старые задачи:** [[Практика 2. Задача 1]] и [[Практика 2. Задача 2]]. В первой условие «нет фамилии» по исходному решению означает NULL; пустая строка — отдельный случай.

**Новая S2:** найти активных, у кого нет компании или score не меньше 150. Затем отдельно найти всех без фамилии, считая отсутствием и NULL, и пустую строку.

> [!success]- Проверка S2
> ```sql
> SELECT id FROM users
> WHERE is_active = 1 AND (company_id IS NULL OR score >= 150)
> ORDER BY id;
> -- 2, 4, 5
> SELECT id FROM users
> WHERE last_name IS NULL OR last_name = ''
> ORDER BY id;
> -- 1, 3, 4, 5
> ```
> Не заменяй первое условие на `company_id = NULL`.

## Блок 2. Все строковые функции и условные выражения

### 3. Регистр, кавычки и шаблоны

| Конструкция | Пример | Смысл |
|---|---|---|
| lower | `lower('HeLLo')` → hello | Нижний регистр |
| upper | `upper('hello')` → HELLO | Верхний регистр |
| initcap | `initcap('new task')` → New Task | Первая буква каждого слова заглавная |
| LIKE | `name LIKE 'New%'` | Регистр учитывается |
| ILIKE | `name ILIKE 'new%'` | Поиск без учёта регистра |
| % | `'%new%'` | Любая последовательность, включая пустую |
| _ | `'a_b'` | Ровно один символ между a и b |

Строки задаются одинарными кавычками: `'ДЕВЕЛОПЕР'`. Двойные кавычки обозначают идентификатор, например `AS "Имя"`. `'%new%'` означает «содержит new», `'new%'` — «начинается с new». В исходной лекции эти пояснения смешаны.

**Новая S3:** на problem сравни `ILIKE 'new%'` и `ILIKE '%new%'`; выведи исходное имя, lower, upper, initcap.

> [!success]- Проверка S3
> Первый шаблон даёт id=20; второй — id=20,30: в Renew есть последовательность new.
> ```sql
> SELECT id, name, lower(name), upper(name), initcap(name)
> FROM problem WHERE name ILIKE '%new%' ORDER BY id;
> ```

### 4. LENGTH, LEFT, RIGHT и POSITION

`length` считает символы; `left(s,n)` берёт первые n; `right(s,n)` — последние n. `position('@' in email)` возвращает позицию первого @, нумерация с 1; если @ нет, возвращается 0.

```sql
SELECT id, username,
       length(username) AS length_username,
       left(username, 2) AS prefix,
       right(email, length(email) - position('@' IN email)) AS domain
FROM users
ORDER BY length_username DESC, id;
```

Для `a@bk.ru`: длина 7, @ на позиции 2; справа нужно взять 7−2=5 символов. Выражение `right(email, position('@' in email))` из лекции берёт неверное количество.

На исходных учебных адресах предполагается корректный формат. Для строки без @ это выражение вернёт целую строку; если требуется проверка формата, это надо явно задать отдельно.

**Старые задачи:** [[Практика 3. Задача 1]], [[Практика 3. Задача 2]], [[Практика 3. Задача 3]].

**Новая S4:** найти точный домен bk.ru независимо от регистра. Адреса с notbk.ru и bk.ru.evil.test должны быть исключены.

> [!success]- Проверка S4
> ```sql
> SELECT id, username, email FROM users
> WHERE position('@' IN email) > 0
>   AND lower(right(email, length(email) - position('@' IN email))) = 'bk.ru'

> ```
> id=1,5. Поиск `LIKE '%bk.ru%'` ошибочно добавит id=3,6 и пропустит верхний регистр id=5.

### 5. CONCAT, ||, CONCAT_WS, COALESCE и NULLIF

```sql
SELECT
    'А' || NULL AS a,
    concat('А', NULL, 'Б') AS b,
    concat_ws(' ', 'Анна', NULL, 'Иванова') AS c,
    coalesce(NULL, '', 'Запасное') AS d,
    nullif('', '') AS e;
```

Результаты: a=NULL; b=АБ; c=Анна Иванова; d=пустая строка; e=NULL. COALESCE ищет первый **не NULL**, а не первый непустой текст. NULLIF превращает совпадающее значение в NULL.

```sql
SELECT id, username,
       'Идентификатор пользователя равен ' || id AS text_user_id,
       coalesce(nullif(first_name, ''), nullif(last_name, ''),
                'Дорогой друг') AS display_name,
       concat_ws(' ', nullif(first_name, ''), nullif(last_name, '')) AS full_name
FROM users ORDER BY id;
```

В `display_name` выбирается одно приветственное имя, в `full_name` склеиваются части. Это разные условия задач.

**Старые задачи:** [[Практика 4. Задача 1]] и [[Практика 4. Задача 2]]. В первой нужен алиас text_user_id. Во второй исходное решение дважды проверяет first_name; во второй ветви должна проверяться last_name.

**Новая S5:** получить приветственное имя с обработкой пустых строк и ФИО через разделитель.

> [!success]- Контроль S5
> display_name для id 1–6: Анна, Белов, Дорогой друг, Дорогой друг, Ева, Фёдор.
> full_name для id=3,4 — пустая строка. Чтобы заменить её, оберни результат: `coalesce(nullif(concat_ws(...), ''), 'Дорогой друг')`.

### 6. CASE: порядок и границы

```sql
SELECT id, score,
       CASE
           WHEN score > 300 THEN 'Мастер'
           WHEN score > 150 THEN 'Эксперт'
           WHEN score > 75 THEN 'Продвинутый'
           ELSE 'Новичок'

FROM users ORDER BY id;
```

Срабатывает первая истинная ветвь. Если начать с `score > 75`, до проверки >300 высокие значения не дойдут. При score=NULL все сравнения неизвестны и выполнится ELSE; если для отсутствующего опыта нужен отдельный статус, добавь `WHEN score IS NULL`.

**Старая задача:** [[Практика 4. Задача 3]] — восстанови точные пороги 300,150,75 со строгим >.

### 7. TO_CHAR, DATE_TRUNC, MAKE_DATE и NOW

```sql
SELECT id, date_joined,
       to_char(date_joined, 'DD Mon YYYY') AS formatted_date,
       to_char(date_joined, 'YYYY-MM') AS year_month,
```

### 8. INTERVAL, EXTRACT и разность дат

```sql
SELECT
    make_date(2022, 1, 1) + interval '45 days' AS upper_bound,
    DATE '2022-01-03' - DATE '2022-01-01' AS days,
    TIMESTAMP '2022-01-03 03:30:00'
      - TIMESTAMP '2022-01-01 00:00:00' AS elapsed;
SELECT
    extract(year FROM TIMESTAMP '2022-02-14 23:59:59') AS y,
    extract(month FROM TIMESTAMP '2022-02-14 23:59:59') AS m,
    extract(hour FROM INTERVAL '2 days 3 hours 30 minutes') AS h;
```

DATE−DATE даёт число дней; TIMESTAMP−TIMESTAMP — интервал. В последнем примере h=3: это компонент часов, а не все 51,5 часа. Лекционная формула «дни×24 + часы» не учитывает минуты и секунды; не называй её точным дробным количеством часов.

**Новая S8:** для интервала 2 дня 3 часа 30 минут объясни результат извлечения days, hours и minutes. Затем вычисли длительность вручную в часах.

> [!success]- Контроль S8
> Компоненты: 2,3,30; полная длительность: 2×24+3+30/60=51,5 часа. Проверка смысловая, не новая функция SQL.

### 9. BETWEEN и полные периоды

BETWEEN включает обе границы. Для timestamp условие до `'2021-04-30'` заканчивается в полночь **начала** 30 апреля. Чтобы включить весь апрель, используй верхнюю исключительную границу 1 мая:

```sql
SELECT id, username, date_joined FROM users
WHERE date_joined >= TIMESTAMP '2021-04-01 00:00:00'
  AND date_joined <  TIMESTAMP '2021-05-01 00:00:00'
ORDER BY date_joined DESC, id;
```

Для «первых 45 суток начиная с 1 января» здесь принимаем интервал [01.01,15.02). Если условие платформы требует включить точную верхнюю границу, используй <= / BETWEEN и явно запиши различие.

### 10. Деление, ::, CAST и DISTINCT

```sql
SELECT 5 / 2 AS integer_result,
       5::numeric / 2 AS decimal_result,
       CAST(5 AS numeric) / 2 AS decimal_cast,
       5 * 1.0 / 2 AS decimal_literal;
SELECT DISTINCT is_active, company_id FROM users;
```

Первый результат 2, остальные — 2,5. Привести к дробному нужно **до** деления: `(5/2)::numeric` уже потеряло дробную часть. DISTINCT сравнивает всю выбранную комбинацию; `DISTINCT id, company_id` не оставляет по одной строке на компанию, если id разный.

## Блок 4. Соединения и перенос навыка на новые задачи

### 11. INNER, LEFT, RIGHT, FULL и отсутствие пары

```sql
SELECT u.id, u.username, c.id AS run_id, c.problem_id
FROM users AS u
LEFT JOIN coderun AS c ON c.user_id = u.id
ORDER BY u.id, c.id;
```

У пользователя 1 две отправки, поэтому он появляется дважды. Пользователи 4,5,6 сохраняются со значениями NULL справа. Это ожидаемая кратность, а не ошибка.

| Вид соединения users с coderun | Строк на стенде | Почему |
|---|---:|---|
| INNER | 4 | Четыре отправки с найденными пользователями |
| LEFT | 7 | Четыре отправки + три пользователя без отправок |
| RIGHT | 4 | Все отправки имеют пользователя |
| FULL | 7 | Здесь совпадает с LEFT; «осиротевших» отправок нет |

FULL не означает арифметическое сложение результатов LEFT и RIGHT с удвоением совпавших пар.

**Новая S11:** найти пользователей, которые не отправляли код.

> [!success]- Проверка S11
> ```sql
> SELECT u.id, u.username
> FROM users AS u
> LEFT JOIN coderun AS c ON c.user_id = u.id
> WHERE c.id IS NULL ORDER BY u.id;
> ```
> id=4,5,6. Проверяем c.id, потому что в стенде у каждой реальной отправки id заполнен.

### 12. ON, WHERE и последующие JOIN

```sql
SELECT u.id, c.id AS run_id
FROM users AS u
LEFT JOIN coderun AS c
  ON c.user_id = u.id
 AND c.created_at >= TIMESTAMP '2021-04-01'
 AND c.created_at < TIMESTAMP '2021-05-01'
ORDER BY u.id, c.id;
```

Сначала ищутся апрельские пары, затем сохраняются все пользователи. Получится 7 строк: две у id=1 и по одной у остальных. Если временное условие перенести в WHERE, строки с NULL будут отброшены и останутся только две отправки пользователя 1.

При цепочке `users LEFT JOIN coderun INNER JOIN problem` пользователи без отправок снова исчезнут: INNER не найдёт им problem. Чтобы сохранить всех, нужна последовательная логика LEFT для необязательных частей.

COALESCE в условии связи, как в третьей лекции с company, подставляет условный идентификатор. Это бизнес-допущение, а не универсальный способ «исправить» отсутствующую компанию.

**Новая S12:** показать всех пользователей, их апрельские отправки и имена задач, сохранив пользователей без отправок.

> [!success]- Проверка S12
> ```sql
> SELECT u.id, u.username, c.id AS run_id, p.name AS problem_name
> FROM users AS u
> LEFT JOIN coderun AS c
>   ON c.user_id=u.id
>  AND c.created_at>=TIMESTAMP '2021-04-01'
>  AND c.created_at<TIMESTAMP '2021-05-01'
> LEFT JOIN problem AS p ON p.id=c.problem_id
> ORDER BY u.id, c.id;
> ```
> 7 строк. У id=1 — Alpha task и New network, у остальных problem_name=NULL.
