## Как проходить повторение

Сначала вспомни правило и напиши свою попытку. Затем прочитай разбор, выполни старое задание на вымышленных данных, реши новую задачу и проверь несколько входов. Ответы в свёрнутых блоках открывай после попытки.

Четыре блока — логическое деление, а не требование вспомнить всё за три часа. Останавливайся между темами и записывай точку продолжения в [[03 — Журнал пробелов]]. Готовность определяется самостоятельным кодом и проверкой, а не временем чтения.

Все фрагменты относятся к встроенному языку BSL, а не к языку запросов 1С. Запускай их по одному в учебной базе в подходящем клиентском контексте, как в исходном уроке с модулем приложения. Они не требуют создания рабочих документов, справочников или регистров. Метки освоения и личные выводы пока не заполнены.

## Блок 1. Учебная среда и первая программа

### 1. Установка, платформа, конфигурация и информационная база

Платформа исполняет прикладное решение. Конфигурация описывает объекты и код. Информационная база объединяет прикладную структуру и данные конкретной среды. В Конфигураторе могут различаться редактируемая основная конфигурация и конфигурация базы данных: после редактирования нужно применить изменение к базе, а затем проверить выполнение.

В «1С:Предприятии» пользователь работает с данными. В Конфигураторе разработчик меняет решение и запускает отладку. Возможность открыть Конфигуратор не доказывает, что изменение уже применяется в пользовательском режиме.

| Операция из исходных заметок | Что делает | Что проверить |
|---|---|---|
| Администрирование → Выгрузить информационную базу | Создаёт DT с конфигурацией и данными | Учебная база выбрана правильно, файл сохранён |
| Администрирование → Загрузить информационную базу | Загружает DT с заменой текущего содержимого | Только отдельная учебная копия, не единственная база |
| Конфигурация → Сохранить конфигурацию в файл | Создаёт CF без пользовательских данных | Это не полноценная копия ИБ |
| Конфигурация → Загрузить конфигурацию из файла | Загружает конфигурацию из CF | Сравнить ожидаемые изменения до применения |
| F7 в описанном учебном сценарии | Обновление конфигурации базы данных | Сначала сохранить редактирование, прочитать подтверждение изменений |
| F5 | Запуск приложения для отладки | Проверить выбранную базу и результат кода |

**Вспомни:** что потеряется, если считать CF резервной копией всех данных? Почему сохранение кода и его выполнение — разные шаги?

**Новая C1:** на бумаге опиши восстановление учебной базы после неудачного эксперимента. Укажи исходную базу, резервную копию, отдельную тестовую базу и проверку результата. Саму загрузку ради упражнения выполнять не требуется.

> [!success]- Проверка C1
> Верный план сохраняет текущую копию, использует DT для восстановления в отдельную учебную базу, проверяет запуск и учебные данные. Использование только CF не возвращает пользовательские данные. Рабочая база не участвует.

### 2. Первая программа: объект, свойство и метод

```bsl
Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = "Привет, учебная база!";
Сообщение.Сообщить();
```

- `Новый` создаёт объект.
- `Сообщение` — имя переменной, через которую обращаемся к объекту.
- `.Текст` — свойство объекта: ему присваивается значение.
- `.Сообщить()` — метод, выполняющий действие.
- `;` завершает оператор; текст в двойных кавычках — строка.
- `//` начинает комментарий до конца строки.

При повторном присваивании `Сообщение.Текст` прежний текст заменяется. Два вызова метода после двух присваиваний выводят последнее значение дважды:

```bsl
Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = "Первый";
Сообщение.Текст = "Второй";
Сообщение.Сообщить();
Сообщение.Сообщить();
```

**Новая C2:** исправь фрагмент, чтобы сообщения были «Первый», затем «Второй». Объясни, почему недостаточно добавить вызовы в самый конец.

> [!success]- Проверка C2
> ```bsl
> Сообщение = Новый СообщениеПользователю;
> Сообщение.Текст = "Первый";
> Сообщение.Сообщить();
> Сообщение.Текст = "Второй";
> Сообщение.Сообщить();
> ```
> Каждый вызов выводит текущее содержимое свойства. Переменная объекта не хранит историю присваиваний.

## Блок 2. Все изученные типы, операции и форматирование

### 3. Строка, число, булево и дата

```bsl
Название = "Учебный пример";
Количество = 3;
Цена = 125.50;
Доступен = Истина;
ДатаПроверки = Дата(2026, 10, 26);
```

`"123"` — строка, `123` — число. Пустая строка `""` отличается от `" "`, содержащей пробел. Булево — `Истина` или `Ложь`, без кавычек. `"Истина"` — текст. В исходной задаче вопрос «Вы мужчина?» записан строкой «Мужчина»; если цель — логический ответ, нужен именно булев тип.

Дату можно задавать литералом `'20261026'`, конструктором `Дата(2026,10,26)` или преобразованием допустимой строки. Для даты со временем: `Дата(2026,10,26,14,30,0)`. Не путай одинарные кавычки литерала даты и двойные кавычки строки.

**Новая C3:** создай вымышленную карточку устройства: название (строка), номер учебного места (число), исправно (булево), дата проверки (дата). Выведи четыре подписанных значения одним сообщением.

> [!success]- Один вариант C3
> ```bsl
> Название = "Учебный ПК";
> НомерМеста = 12;
> Исправно = Истина;
> ДатаПроверки = Дата(2026, 10, 26);
> Сообщение = Новый СообщениеПользователю;
> Сообщение.Текст = Название + Символы.ПС
>     + "Место: " + Строка(НомерМеста) + Символы.ПС
>     + "Состояние: " + Формат(Исправно, "БИ=Исправно;БЛ=Неисправно")
>     + Символы.ПС + Формат(ДатаПроверки, "ДФ=dd.MM.yyyy");
> Сообщение.Сообщить();
> ```
> `Символы.ПС` разделяет строки. `Строка()` явно переводит число в текст.

### 4. Арифметика и соединение строк

```bsl
Сумма = 125.50 * 3;
Разница = 20 - 7;
Частное = 9 / 2;
Текст = "Учебная" + " " + "задача";
```

Результаты: 376.5; 13; 4.5; «Учебная задача». Скобки задают нужный порядок вычислений. Вычитание строк не следует использовать как удаление части текста. Для подписанного числового результата делай преобразование явно:

```bsl
Сообщение.Текст = "Сумма: " + Строка(Цена * Количество);
```

**Возвращение к старой задаче типов №3:** четыре выражения должны дать 8. В исходном решении сначала четыре раза присваивается Текст, затем четыре раза вызывается Сообщить. Это не четыре разных результата — требуется чередование присваивания и вызова.

**Новая C4:** четырьмя операциями получи число 12 и выведи четыре результата с названиями операции. Затем измени одно выражение, чтобы получить 12.5.

> [!success]- Проверка C4
> Например: 6+6; 20−8; 3×4; 24/2. Для дробного результата: 25/2.
> Каждое присваивание Текст сопровождается отдельным вызовом Сообщить. Число 12.5 остаётся числом до форматирования.

### 5. Арифметика дат: секунды и разность

```bsl
ИсходнаяДата = Дата(2026, 10, 26);
ЧерезТриДня = ИсходнаяДата + 3 * 24 * 60 * 60;
ДесятьДнейРанее = ИсходнаяДата - 10 * 24 * 60 * 60;
СекундМеждуДатами = ЧерезТриДня - ИсходнаяДата;
ДнейМеждуДатами = СекундМеждуДатами / (24 * 60 * 60);
```

При прибавлении числа к дате число трактуется как секунды. При вычитании даты из даты получается число секунд. Не нужно вычитать «пустую дату», чтобы получить обычную длительность.

В исходной теории встречается сложение календарных дат через вычитание `Дата(1,1,1)`. Не используй это как правило добавления дней, месяцев или лет: календарная дата и длительность имеют разный смысл. Здесь повторяем только простой сдвиг на заданное число суток и разность двух дат.

**Новая C5:** от 26.10.2026 отними десять суток, добавь три и вычисли разницу двух результатов.

> [!success]- Проверка C5
> 16.10.2026; 29.10.2026; разность 13 суток = 1 123 200 секунд. Объясни, почему `Дата - 10` сдвинула бы значение только на 10 секунд.

### 6. ФОРМАТ: представление не меняет исходное значение

```bsl
Цена = 1234.567;
ПредставлениеЦены = Формат(Цена, "ЧДЦ=2;ЧРД=,");
ДатаПроверки = Дата(2026, 10, 26, 14, 30, 0);
ТекстДаты = Формат(ДатаПроверки, "ДФ=dd.MM.yyyy HH:mm:ss");
ПустаяДата = Дата(1, 1, 1);
ТекстОкончания = Формат(ПустаяДата, "ДП='Курс еще не пройден'");
```

| Параметр из курса | Что восстанавливаем |
|---|---|
| ЧЦ | Допустимое число разрядов представления |
| ЧДЦ | Число десятичных знаков |
| ЧРД | Разделитель дробной части |
| ЧГ | Правило группировки разрядов |
| ЧО | Представление отрицательного числа |
| ЧФ | Числовой шаблон с дополнительным текстом |
| ДФ | Явный шаблон даты и времени |
| ДЛФ | Локальное представление даты/времени |
| ДП | Текст для пустой даты |
| БИ / БЛ | Представления истинного и ложного значения |

Для сложного ЧФ, ЧО и локального ДЛФ сверяй результат в своей учебной платформе и синтакс-помощнике: подпись результата не должна зависеть от угаданной локали. Не заучивай декоративный шаблон без проверки.

**Новая C6:** число 1234.567 покажи с двумя знаками после запятой, дату — только день/месяц/год, булево — «Готово» / «Не готово». После вывода проверь, что исходное число всё ещё можно умножать.

> [!success]- Проверка C6
> Для числа: `Формат(1234.567, "ЧДЦ=2;ЧРД=,")`; конец результата 234,57, группировка зависит от настроек.
> Для даты: `Формат(ДатаПроверки, "ДФ=dd.MM.yyyy")` → 26.10.2026.
> Для булева: `Формат(Истина, "БИ=Готово;БЛ=Не готово")` → Готово.
> Формат возвращает строку; само числовое значение 1234.567 не округляется присваиванием его представления другой переменной.

## Блок 3. Условия, тернарное выражение и циклы

### 7. Если, ИначеЕсли, Иначе: взаимоисключающие ветви

```bsl
Возраст = 18;
Если Возраст < 0 Тогда
    Категория = "Ошибка данных";
ИначеЕсли Возраст < 16 Тогда
    Категория = "Не допущен";
ИначеЕсли Возраст < 18 Тогда
    Категория = "Юниор";
Иначе
    Категория = "Взрослый";
КонецЕсли;
```

Выполняется только первая подходящая ветвь. При 16 получится «Юниор», при 18 — «Взрослый». В исходной задаче сначала стоит `Возраст > 16`, поэтому дальнейшая проверка взрослой категории для большинства подходящих возрастов недостижима.

Сравнения: `=`, `<>`, `>`, `<`, `>=`, `<=`. Знак = в присваивании задаёт значение, а внутри условия сравнивает выражения.

**Новая C7:** классифицируй остаток: отрицательный — ошибка, 0 — нет, от 1 до 4 — мало, от 5 — достаточно. Проверь −1,0,1,4,5.

> [!success]- Решение C7
> ```bsl
> Остаток = 4;
> Если Остаток < 0 Тогда
>     Статус = "Ошибка";
> ИначеЕсли Остаток = 0 Тогда
>     Статус = "Нет";
> ИначеЕсли Остаток < 5 Тогда
>     Статус = "Мало";
> Иначе
>     Статус = "Достаточно";
> КонецЕсли;
> ```
> Ожидаемые статусы: Ошибка, Нет, Мало, Мало, Достаточно.

### 8. И, ИЛИ, НЕ и тернарное выражение

`И` требует всех проверок; `ИЛИ` — хотя бы одной; `НЕ` меняет истинность. Сложные группы оформляй скобками, чтобы смысл был очевиден.

```bsl
ДокументПроведен = Истина;
СуммаДокумента = 10000;
КодКонтрагента = "TEST";
Допустим = ДокументПроведен
    И СуммаДокумента >= 10000
    И НЕ (КодКонтрагента = "");
Статус = ?(Допустим, "Принят", "Требует проверки");
```

`?(Условие, ЗначениеЕслиИстина, ЗначениеЕслиЛожь)` возвращает значение. Это удобно для простого выбора, но не заменяет последовательность независимых проверок и действий.

Условие задачи 7 просит использовать И/ИЛИ/НЕ, хотя саму проверку «все три требования выполнены» естественно записать через И. Эквивалентная проверка ошибки: `НЕ ДокументПроведен ИЛИ СуммаДокумента < 10000 ИЛИ КодКонтрагента = ""`. Не добавляй лишний ИЛИ, меняющий бизнес-правило ради формального набора операторов.

**Новая C8:** по оптовому признаку выбрать коэффициент 1.10 или 1.25, затем рассчитать итоговую цену для базы 200.

> [!success]- Проверка C8
> ```bsl
> ОптоваяПродажа = Истина;
> Коэффициент = ?(ОптоваяПродажа, 1.10, 1.25);
> Итог = 200 * Коэффициент;
> ```
> При Истина: 220; при Ложь: 250. Ветви возвращают числа, не строки.

### 9. Незавершённая задача: показать все ошибки документа

В исходной задаче 8 формулировка про дату неоднозначна. Для тренировки явно фиксируем правило: дата заполнена и **не ранее 01.01.2025**, контрагент заполнен, сумма строго больше 10000. Это интерпретация для повторения; при возвращении на платформу проверь исходный текст.

Если нужны **все** ошибки, последовательность `ИначеЕсли` не подходит: она остановится на первой ветви.

**Новая C9:** данные: пустая дата, пустой контрагент, сумма 9999.99. Получи три сообщения об ошибках. Затем замени только сумму на 10000 и объясни, почему ошибка сохраняется.

> [!success]- Решение C9
> ```bsl
> ДатаДокумента = Дата(1, 1, 1);
> Контрагент = "";
> СуммаДокумента = 9999.99;
> Ошибки = "";
> Если ДатаДокумента = Дата(1, 1, 1)
>     ИЛИ ДатаДокумента < Дата(2025, 1, 1) Тогда
>     Ошибки = Ошибки + "Неверная дата" + Символы.ПС;
> КонецЕсли;
> Если Контрагент = "" Тогда
>     Ошибки = Ошибки + "Не заполнен контрагент" + Символы.ПС;
> КонецЕсли;
> Если СуммаДокумента <= 10000 Тогда
>     Ошибки = Ошибки + "Сумма должна быть больше 10000" + Символы.ПС;
> КонецЕсли;
> Сообщение = Новый СообщениеПользователю;
> Сообщение.Текст = ?(Ошибки = "", "Проверка пройдена", Ошибки);
> Сообщение.Сообщить();
> ```
> Три независимых Если собирают все нарушения. При ровно 10000 третья ошибка остаётся. При дате 01.01.2025, контрагенте «Учебный» и сумме 10000.01 — проверка пройдена.

### 10. Пока: условие, тело, шаг и завершение

```bsl
Номер = 1;
Сообщение = Новый СообщениеПользователю;
Пока Номер <= 5 Цикл
    Сообщение.Текст = Строка(Номер);
    Сообщение.Сообщить();
    Номер = Номер + 1;
КонецЦикла;
```

На входе проверяется условие, затем выполняется тело и меняется номер. Последний выведенный номер 5; после шага номер становится 6, условие ложно. Если изначально Номер=6, тело не выполнится.

| Итерация | Номер перед условием | Условие | Вывод | Номер после шага |
|---:|---:|---|---:|---:|
| 1 | 1 | Истина | 1 | 2 |
| 2 | 2 | Истина | 2 | 3 |
| 3 | 3 | Истина | 3 | 4 |
| 4 | 4 | Истина | 4 | 5 |
| 5 | 5 | Истина | 5 | 6 |

В исходной задаче с пятью сообщениями условие использует ТелоЦикла, а шаг меняет ЧислоЦикла. Нужная переменная не меняется — цикл не завершится. Не запускай такой фрагмент до исправления.

**Новая C10:** выведи чётные 2,4,6,8,10 и отдельно их сумму.

> [!success]- Решение C10
> ```bsl
> Номер = 2;
> Сумма = 0;
> Сообщение = Новый СообщениеПользователю;
> Пока Номер <= 10 Цикл
>     Сумма = Сумма + Номер;
>     Сообщение.Текст = Строка(Номер);
>     Сообщение.Сообщить();
>     Номер = Номер + 2;
> КонецЦикла;
> Сообщение.Текст = "Сумма: " + Строка(Сумма);
> Сообщение.Сообщить();
> ```
> Пять проходов, сумма 30, после цикла Номер=12.

### 11. Для, обратный вывод и вложенные циклы

```bsl
Сообщение = Новый СообщениеПользователю;
Для Счетчик = 1 По 9 Цикл
    Сообщение.Текст = Строка(10 - Счетчик);
    Сообщение.Сообщить();
КонецЦикла;
```

Обычный числовой Для увеличивает счётчик; для вывода 9…1 в исходном курсе меняется выводимое выражение, а не направление счётчика. Не переноси синтаксис `Шаг -1` из другого языка.

```bsl
Для Множитель = 1 По 9 Цикл
    Для ВторойМножитель = 1 По 9 Цикл
        Сообщение.Текст = Строка(Множитель) + " * "
            + Строка(ВторойМножитель) + " = "
            + Строка(Множитель * ВторойМножитель);
        Сообщение.Сообщить();
    КонецЦикла;
КонецЦикла;
```

Внешний цикл выбирает строку таблицы умножения, внутренний проходит её столбцы заново. Всего 9×9=81 сообщение.

**Новая C11:** построй таблицу произведений для первого множителя 2…4 и второго 1…3. Сначала предскажи количество сообщений и последний результат.

> [!success]- Проверка C11
> Замени границы двух Для на 2 По 4 и 1 По 3. Получится 9 сообщений; первое «2 * 1 = 2», последнее «4 * 3 = 12».
> Если используешь внутренний Пока, его счётчик нужно заново инициализировать внутри внешнего цикла.

## Блок 4. Структуры, сопоставление и итоговая программа

### 12. Создание, вставка и чтение структуры

Структура — коллекция именованных значений. Ключ уникален и соответствует правилам идентификатора: буква или подчёркивание в начале, затем буквы/цифры/подчёркивания, без пробелов. Значения могут иметь разные типы.

```bsl
Устройство = Новый Структура;
Устройство.Вставить("Название", "Учебный ПК");
Устройство.Вставить("Место", 12);
Устройство.Вставить("Исправно", Истина);
Название = Устройство.Название;
Номер = Устройство["Место"];
Устройство["Место"] = 15;
Устройство.Вставить("Место", 20);
```

Повторная вставка существующего ключа заменяет значение, а не создаёт второй элемент. После кода Место=20. Переменная Номер, прочитанная раньше, остаётся 12.

Конструктор `Новый Структура("Название,Место")` создаёт **обычную** структуру с заранее заданными ключами. Фиксированной она становится только после создания `Новый ФиксированнаяСтруктура(Устройство)`. У фиксированной структуры нельзя менять её пары ключ–значение; это не просто запрет добавления новых ключей.

### 13. Для каждого и связь двух структур

```bsl
Сообщение = Новый СообщениеПользователю;
Для Каждого Элемент Из Устройство Цикл
    Сообщение.Текст = Элемент.Ключ + ": " + Строка(Элемент.Значение);
    Сообщение.Сообщить();
КонецЦикла;
```

Элемент — пара с полями Ключ и Значение, а не само значение. Порядок перебора не используй как критерий соответствия двух коллекций: соответствие определяется ключом.

В исходной практике структуры содержат имена и описания родственников; при повторении используем вымышленные устройства. Сам принцип — сопоставление записей по одному ключу.

**Новая C12:** в одной структуре хранятся названия устройств, в другой — их состояния. Выведи название и состояние; если состояния нет, покажи «Нет данных».

> [!success]- Решение C12
> ```bsl
> Названия = Новый Структура;
> Названия.Вставить("ПК1", "Учебный ПК");
> Названия.Вставить("Принтер1", "Учебный принтер");
> Названия.Вставить("Камера1", "Учебная камера");
> Состояния = Новый Структура;
> Состояния.Вставить("ПК1", "Исправно");
> Состояния.Вставить("Принтер1", "Проверить");
> Сообщение = Новый СообщениеПользователю;
> Для Каждого Устройство Из Названия Цикл
>     НайденноеСостояние = "Нет данных";
>     Для Каждого Состояние Из Состояния Цикл
>         Если Состояние.Ключ = Устройство.Ключ Тогда
>             НайденноеСостояние = Состояние.Значение;
>         КонецЕсли;
>     КонецЦикла;
>     Сообщение.Текст = Устройство.Значение + ": " + НайденноеСостояние;
>     Сообщение.Сообщить();
> КонецЦикла;
> ```
> Три сообщения: ПК — Исправно, принтер — Проверить, камера — Нет данных.
> Запасное значение сбрасывается **для каждого** устройства. Иначе камера может ошибочно получить состояние предыдущего.

Вложенный перебор соответствует пройденному решению. Более прямой поиск по ключу через `Свойство()` был добавлен в прежнюю обзорную страницу, но в исходных уроках не разобран; для обязательного повторения здесь достаточно изученного сопоставления ключей.

## Итоговая задача: учебная проверка трёх устройств

Используй только пройденные типы, структуры, условия, циклы и сообщения.

**Данные:**

- Названия: ПК1 → «Учебный ПК», Принтер1 → «Учебный принтер», Камера1 → «Учебная камера».
- Остатки расходников: ПК1 → 0, Принтер1 → 3; для Камера1 данных нет.
- Порог достаточного остатка: 5.
- Дата проверки: 26.10.2026.
- Число дней до следующей проверки: 7.

**Требуется:**

1. Создать две обычные структуры, затем фиксированную копию названий.
2. Для каждого устройства искать остаток по ключу.
3. Различать «Нет данных», «Нет расходников», «Мало», «Достаточно» и отрицательное некорректное значение.
4. Вывести название, статус, дату проверки и дату через семь суток.
5. Посчитать общее число обработанных устройств.
6. Сохранить свой код и кратко объяснить каждую конструкцию.
7. Изменить входы и повторно проверить программу.

**Важный вопрос:** почему нельзя использовать 0 как признак «значение не найдено»? Потому что 0 — допустимый известный остаток. Нужен отдельный булев флаг найденного значения.

> [!success]- Контроль алгоритма без полного готового кода
> Перед внешним циклом: Счетчик=0. Внутри: Найдено=Ложь, Остаток=0. Внутренний цикл сравнивает ключи; при совпадении присваивает остаток и Найдено=Истина.
> После поиска: сначала НЕ Найдено, затем Остаток<0, затем =0, затем <5, затем Иначе.
> Счётчик увеличивается один раз на устройство, а не на совпадение.
> На исходных данных: ПК — Нет расходников; принтер — Мало; камера — Нет данных. Обработано 3. Следующая проверка 02.11.2026.
> Новые входы: остаток принтера 5 → Достаточно; −1 → Ошибка данных; добавление камеры с 0 → Нет расходников. Это четыре разных сценария, которые нельзя смешивать.

## Проверка ошибок перед возвращением к курсу

Объясни и исправь без подсказки:

1. Четыре присваивания Текст, затем четыре вызова Сообщить.
2. В Пока проверяется Счетчик, а изменяется ДругаяПеременная.
3. Первая ветвь Возраст>16 перехватывает взрослые значения до их классификации.
4. ИначеЕсли используется, когда нужны все три сообщения об ошибках.
5. Список ключей в конструкторе Структура объявлен фиксированной структурой.
6. Вторая структура сопоставляется с первой по позиции вместо ключа.
7. Десять дней вычитаются из даты как число 10.
8. Отформатированная строка используется как исходное число.
9. После поиска отсутствующего ключа остаётся состояние предыдущего устройства.
10. Условие «сумма строго больше 10000» проверяется через >=10000.
