# Практическое закрепление курсов

## Минимальный пакет усвоения

Для каждого курса достаточно не большого проекта, а компактного набора:

1. собственный конспект ключевой темы;
2. ответы на контрольные вопросы;
3. одна небольшая практическая работа;
4. один разбор ошибки или неправильного подхода;
5. собственный итоговый вывод;
6. одна связь с работой, другим курсом или профессиональной задачей.

Курс не получает новый большой проект, если существующий навык можно подтвердить одним безопасным воспроизводимым артефактом.

## Минимальный скриптинг как встроенный навык

Отдельный курс Python перенесён в архив. При необходимости внутри ИБ или администрирования допускается одна короткая задача: понять назначение скрипта, проверить его структуру, безопасно изменить параметр, выполнить на тестовых данных и сравнить результат с ожидаемым. Заготовка от ИИ не считается проверенной до ручного чтения и тестового запуска.

## Контрольные вопросы по группам

### Сети

1. Как определить, на каком уровне возникает проблема?
2. Как связаны адрес, маска, шлюз, DNS и маршрут?
3. Какие поля пакета подтверждают гипотезу?
4. Чем отсутствие ответа отличается от неправильного ответа?
5. Как проверить исправление повторно?

### 1С

1. Где выполняется код и с какими данными он работает?
2. Почему выбран конкретный тип данных?
3. Как обрабатывается неправильный ввод?
4. Когда нужен цикл, а когда условие?
5. Как проверить результат на нескольких наборах данных?

### Кибербезопасность

1. Какой актив и какой ущерб рассматриваются?
2. Какое действие нарушителя ожидается?
3. Какой источник событий это покажет?
4. Какая мера предотвращает, а какая обнаруживает?
5. Что делать после срабатывания?

### Анализ событий

1. Какова гипотеза запроса?
2. Какие поля обязательны?
3. Как ограничен временной диапазон?
4. Как отличить нормальное событие от подозрительного?
5. Что может вызвать ложное срабатывание?

## Разбор ошибки

Каждый практический артефакт должен содержать хотя бы один честный разбор:

| Поле | Вопрос |
|---|---|
| Симптом | Что получилось не так? |
| Гипотеза | Почему это могло произойти? |
| Проверка | Как гипотеза проверялась? |
| Причина | Что подтверждено фактами? |
| Исправление | Какое минимальное изменение внесено? |
| Повторная проверка | Как доказано, что результат исправлен? |
| Переносимый вывод | Что делать в похожей ситуации? |

## Уровни усвоения

| Уровень | Критерий |
|---:|---|
| 1. Ознакомился | Узнаю понятие и могу найти связанный материал |
| 2. Понимаю | Объясняю своими словами без копирования определения |
| 3. Выполнил по инструкции | Повторил готовый алгоритм и получил ожидаемый результат |
| 4. Выполнил самостоятельно | Решил аналогичную задачу без пошаговой подсказки |
| 5. Могу диагностировать | Нахожу типовые ошибки и проверяю гипотезы |
| 6. Закреплено | Повторно выполнил после перерыва |
| 7. Подтверждено | Существует безопасный артефакт или рабочий кейс |

## Минимально достаточный уровень перехода

| Курс или навык | Минимальный уровень | Почему достаточно |
|---|---|---|
| Компьютерные сети | 5. Могу диагностировать | Сети являются зависимостью для ИБ, ViPNet и текущей работы |
| Базовый BSL | 4. Выполнил самостоятельно | Этого достаточно для перехода к следующему существующему блоку |
| Специалист по кибербезопасности | 4 по одному сквозному кейсу; 3 по отдельным лабораториям | Не требуется одинаковая глубина по всем технологиям |
| Противодействие кибератакам | 4 для одного запроса и 5 для одной ошибки детекции | Курс специализируется на анализе и диагностике |
| SQL | 4 для набора связанных запросов | Позволяет применять язык к данным без полного курса СУБД |
| Минимальный скриптинг | 3 для одной безопасной задачи внутри курса | Скриптинг является инструментом, а не отдельным учебным направлением |
| ViPNet без стенда | 2 для архитектуры и алгоритмов | Продуктовые действия без ViPNet не подтверждаются |
| ViPNet на официальном стенде | 3 или уровень, заданный КИМ | Точный критерий зависит от официальной программы |

## Связь с работой

- сеть: использовать только обезличенный типовой сценарий доступности, не реальный объект;
- 1С: воспроизводить пользовательский сценарий только на учебной базе;
- PowerShell: автоматизировать безопасную проверку локальной учебной машины;
- мониторинг: брать синтетические события, а не данные Zabbix работодателя;
- документация: применять структуру Jira/Confluence «симптомы → действия → результат», не копируя рабочие тексты.
