## Ошибка цепочки сертификатов при подключении SSMS

### Симптом

Соединение с SQL Server устанавливается, но SSMS сообщает:

«Цепочка сертификатов выпущена центром сертификации,
не имеющим доверия».

### Причина

SQL Server использует автоматически созданный самоподписанный
сертификат, которому клиент SSMS не доверяет.

### Решение для учебного стенда

В параметрах подключения включить Trust server certificate
или добавить параметр:

TrustServerCertificate=True

### Для рабочей среды

Установить на SQL Server действующий сертификат от доверенного
центра сертификации.

## Сетевой доступ к SQL Server

Для экземпляра MSSQLSERVER включён протокол TCP/IP.

- Статический TCP-порт: 1433
- Динамические порты: отключены
- Служба MSSQLSERVER перезапущена
- В Windows Firewall разрешён TCP 1433 только:
  - локальный адрес: 192.168.110.10
  - источник: 192.168.110.0/28

Статический порт необходим, чтобы приложения и правила межсетевого
экрана обращались к предсказуемому порту SQL Server.

## Проверка работоспособности

Командой Test-NetConnection проверено подключение к
192.168.110.10:1433.

Результат: TcpTestSucceeded = True.

Через SSMS выполнено подключение:

- сервер: 192.168.110.10,1433
- тип: Database Engine
- аутентификация: SQL Server Authentication
- учётная запись: sa

Создана учебная база ViPNet_Training и таблица dbo.LabChecks.
Выполнены операции CREATE DATABASE, CREATE TABLE, INSERT и SELECT.
