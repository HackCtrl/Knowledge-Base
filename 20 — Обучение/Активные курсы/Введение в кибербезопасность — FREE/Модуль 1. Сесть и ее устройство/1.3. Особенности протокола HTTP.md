### **Протокол HTTP/HTTPS** 

**HTTP** - это текстовый протокол, который определяет структуру запросов и ответов между клиентом и сервером "запрос-ответ"
1. Клиент инициирует соединение с сервером, отправляя HTTP-запрос 
2. Сервер обрабатывает запрос и отправляет HTTP-ответ 

**Особенности HHTP:** 
- HTTP по умолчанию использует порт 80 
- Открытая передача данных 

**HTTPS** - это расширение HTTP, обеспечивающее шифрование данных с использованием SSL/TLS 

Особенности HTTPS: 
1. Клиент устанавливает TCP-соединение с сервером на порт 443 
2. Шифрование данных 

### **Методы HTTP/HTTPS** 

##### 1. **GET** 
- используется для запроса данных с сервера 
- пример: получение веб страницы 
- данные передаются в URL запросе 
##### 2. **POST**
- передача данных на сервер для обработки 
- для создания или обновления ресурсов 
- данные отправляются в теле запроса 
##### 3. **PUT** 
- полное обновление ресурсов на сервере 
- пример: загрузка нового файла на сервер 
##### 4. **DELETE** 
- удаление ресурса с сервера 
- пример: удаление записи с БД 
##### 5. **HEAD** 
- запрашивает только заголовки ответа, без тела 
- используется для проверки доступности ресурса 
##### 6. **OPTIONS** 
- определяет методы, поддерживаемые сервером для определенного ресурса 
##### 7. **PATCH** 
- частичное обновление ресурса 
- пример: изменение одного поля в записи БД 

### **Структура HTTP-запроса** 

**HTTP-запрос состоит из следующих частей:** 
##### 1. **Стартовая строка определяет метод, URL и версию протокола** 
```
GET /index.html HTTP/1.1
```
##### 2. **Заголовки (Headers) передают метаинформацию о запросе** 
```
Host: example.com
User-Agent: Mozilla/5.0
```
##### 3. **Тело (Body) используется в запросах, таких как POST или PUT, для передачи данных** 

### **Коды состояния HTTP** 

Это трехзначные числовые коды, которые сервер возвращает клиенту в ответ на HTTP-запрос. Делятся на 5 категорий: 
##### 1. **1xx: информационные (informational)**
	Информируют клиента о продолжение обрабокти запроса 
- **100 Continue**: клиент может продолжить отправку запроса
- **101 Switching Protocols**: сервер переключается на другой протокол (например, WebSocket)
##### 2. **2xx: успешные (Success)**
	 Означает, что запрос был успешно выполнен 
- **200 OK**: запрос выполнен успешно. Например, сервер вернул HTML-страницу
- **201 Created**: ресурс успешно создан (например, новая запись в базе данных)
- **204 No Content**: запрос обработан, но тело ответа отсутствует
##### 3. **204 No Content**: запрос обработан, но тело ответа отсутствует
	 Указывают, что для завершения обработки нужно перейти по другому URL 
- **301 Moved Permanently**: ресурс перемещён на новый URL навсегда
- **302 Found**: ресурс временно доступен по другому URL
- **304 Not Modified**: ресурс не изменился с момента последнего запроса (используется кеш)
##### 4. **4xx: ошибки клиента (Client Errors)**
	 Возникают из-за некорректно запроса со стороны клиента 
- **400 Bad Request**: некорректный запрос (например, синтаксическая ошибка)
- **401 Unauthorized**: необходима авторизация
- **401 Unauthorized**: необходима авторизация
- **404 Not Found**: ресурс не найден на сервере
##### 5. **5xx: ошибки сервера (Server Errors)**
	 Возникают из за проблем со стороны сервера 
- **500 Internal Server Error**: внутренняя ошибка сервера
- **501 Not Implemented**: сервер не поддерживает указанный метод
- **502 Bad Gateway**: проблема с промежуточным сервером (например, прокси)
- **503 Service Unavailable**: сервер временно недоступен (перегрузка или техобслуживание)
- **503 Service Unavailable**: сервер временно недоступен (перегрузка или техобслуживание)
