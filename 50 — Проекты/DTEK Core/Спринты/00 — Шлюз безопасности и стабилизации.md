# Шлюз безопасности и стабилизации

> [!danger] Обязательный этап
> Ни один новый продуктовый спринт не начинается, пока этот контрольный этап не закрыт фактическими проверками.

## Зачем он нужен

Контрольный аудит подтвердил функциональность MVP, но выявил блокирующие проблемы в разграничении прав, блокировке пользователей, межтенантных связях и атомарности ключевых сценариев.

## Порядок работ

- [ ] SEC-01 — закрыть повышение привилегий через профиль
- [ ] SEC-02 — реально отзывать доступ заблокированного пользователя
- [ ] SEC-03 — исключить межтенантную связь объекта и риска
- [ ] SEC-04 — исключить межтенантные связи Trust Graph
- [ ] STAB-01 — сделать создание организации атомарным
- [ ] STAB-02 — сделать принятие приглашения идемпотентным и безопасным
- [ ] STAB-03 — сгенерировать реальные TypeScript-типы Supabase
- [ ] STAB-04 — добавить DB-level RLS integration tests
- [ ] STAB-05 — провести авторизованный QA по ролям

## Условие завершения

Все автоматические проверки, двухтенантная матрица, ручная приёмка, миграционная сверка и готовность к пилоту должны иметь фактический результат. Документ без прогона не считается доказательством.
